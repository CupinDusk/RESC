# Auditor execution record

No `benchmark.exe time` invocation was made by this audit. No author performance launcher was executed. No producer file was edited.

1. A first build command used the parent working directory but mistakenly created the fully repeated relative `outputs/.../independent` path. Zig reported `unable to open output directory 'independent': FileNotFound`. The auditor-created empty `outputs` tree was removed only after resolving the exact absolute path within the assigned experiment directory and checking recursively that it contained no files.
2. The correct `independent/` directory was created. From the assigned parent directory, the bundled Zig command `c++ -O3 -DNDEBUG -std=c++17 -Wall -Wextra benchmark.cpp -o independent/benchmark.exe` succeeded without diagnostics.
3. A second command selected `independent/` as working directory but still used source/output paths relative to the parent. Census compilation failed to find its output directory, input copies failed, and rebuilt validation printed `inputs missing`. It did not reach or alter original validation output.
4. With `independent/` as working directory, Zig compiled `../census.cpp -o census.exe` with the same flags. It emitted `warning: variable 'b' is used uninitialized whenever '&&' condition is false [-Wsometimes-uninitialized]` at census.cpp:13. The warning and the unreachable path are analyzed in the audit; the source was not changed.
5. Parent `inputs.txt` and `schedule.txt` were copied here. `./benchmark.exe validate` printed `PASS_VALIDATION distinct_queries=720 raw/closed_BF_certificates_and_Floyd complete_batch_hashes=60`. `./census.exe` completed successfully. Both programs wrote only to this directory.
6. Zig emitted `benchmark.s` from `../benchmark.cpp` with the same optimization flags plus `-S -masm=intel`, without diagnostics. This generated assembly was read for actual optimization and timing-loop behavior.
7. First independent Python-checker run failed its byte-exact text serialization assertion because it assumed LF. Windows `Path.write_text` actually produces CRLF; parsed data agreed. The checker was corrected to reconstruct the exact platform serialization. Original bytes were unchanged.
8. The next checker run reexecuted the original generator only into `generator-replay/`, after redirecting `HERE` and `OLD` assignments. Its sources/inputs/schedule/manifest matched exactly. It then failed PE normalization because the checker initially normalized COFF timestamp and RSDS GUID but not two timestamp copies in `.buildid`. That failed result remains in `FAILURE_PRESERVED.json`.
9. Explicit PE header parsing established the remaining offsets 799748..799751 and 799776..799779 as `IMAGE_DEBUG_DIRECTORY.TimeDateStamp` fields, both exactly equal to the respective original/rebuilt COFF timestamp. Final normalization removes only those copies, the COFF timestamp and the build GUID; all remaining PE bytes match.
10. The final independent checker completed all input/source/manifest, assignment/quartet, graph/certificate, hash, row/order/repeat, executable and statistical checks. It is run with bundled Python using `-B -X utf8`; no global environment or package settings are changed. The checker is rerunnable for validation and never executes performance mode.
